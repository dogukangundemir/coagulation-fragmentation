# F11 - Maze-hard test results: board-exact vs strict accuracy across arms

Figures: `maze_hard_results.png` (results table + bar panel),
`maze_hard_T_sweep.png`, `maze_hard_examples.png`, `maze_hard_coverage.png`.
All are regenerated by `scripts/figures/maze_hard_results.py` (CPU only);
every number is read back from the tracked CSVs in this folder
(`data.csv`, `permaze_iou.csv`, `example_grids.csv`) or recomputed live from
the external result trees when `--families-dir` / `--baselines-dir` are given.

## maze_hard_results.png - table + grouped bars

**Caption.** On the 1000-maze Maze-hard test split (30x30,
sapientinc/maze-30x30-hard-1k), board-exact accuracy stays near zero for every
arm tested here: CF-WallAware (cross kernel, hid 16) 0.0% board-exact and
0.0% strict (120 epochs x 3 seeds, 5,889 effective parameters); the transport
CF physics-only arm 0.0% board-exact / 0.4% strict (4/1000 at T=8, 0 learned
parameters); WONN official code at a reduced 150/9000-epoch budget 0.1%
board-exact (EMA checkpoint) / 8.4% (raw model.pth), strict never computed
(not a reproduction of the paper's 76.2% at 9000 epochs). Adding a seeded
tie-break (K=4 random starts, lowest dissipation kept) to the physics arm
raises strict to 98/300 (32.7%) on the first 300 test mazes while
board-exact stays 0/300.

**How to read.** Table and bars show the same numbers. Blue = board-exact
(predicted 30x30 label grid equals the single reference route cell-for-cell;
the metric of the WONN reference code), green = strict (the predicted cells
form any wall-free simple start-to-goal path of the reference length). The
dashed grey line is the published WONN paper result (76.2%, Table 3, p. 9,
9000 epochs, 0.396M parameters) - not run by us, shown for scale. CF-WallAware
values are means over 3 seeds (0, 1, 2); "n computed" means the official
evaluation never recorded the metric.

**Key takeaway.** Two different claims live in this figure. First: at our
budgets no arm solves Maze-hard boards outright. Second, and the important
one: strict beats board-exact only where route ties are broken - the physics
tie-break goes from 1/300 to 98/300 strict passes while board-exact stays
0, because every one of the 1000 test mazes is *tied* (more than one equally
short start-to-goal route exists), so a solver can emit a perfectly valid
alternative route and pass strict while necessarily failing board-exact.
Board-exact is therefore strictly harder than strict on this split, and
exact <= strict must hold, never exact == strict being assumed.

**Data source.** `data.csv` rows `results_table` (arms: CF-WallAware (ours),
WONN official (EMA), WONN official (non-EMA), Physics, exact solve, Physics +
tie-break (K=4), Published WONN (paper)); upstream records:
`maze_hard_cf/results.json`, `transport_mazehard/results.json`,
`transport_mazehard_tie/results.json`,
`wonn_tools/out/run_record.json` (external, read-only, passed via CLI args).

**Caveats.** No two arms are budget-matched (epochs, seeds, hardware all
differ; the CF arm used CUDA, the physics arm CPU). The WONN run is a
reduced-budget pipeline check (150/9000 epochs, batch 32 vs official 64,
single seed 137) - not a reproduction; its strict cell is missing, not zero.
The tie-break row uses only the first 300 test mazes (labelled in the
panel). CF mean recall of the reference route is 0.98 at T*=16, but with
roughly 97 extra lit cells per maze on average, which is why mean IoU is
only 0.545 despite the high recall.

## maze_hard_T_sweep.png - accuracy vs read-out horizon

**Caption.** Test accuracy (strict and board-exact, identical at every
recorded point) of CF-WallAware versus read-out horizon T in {16, 24, 32, 48},
120-epoch runs at trained depth T=24, one line per training seed.
**How to read.** y = strict accuracy in % of the 1000 test mazes (linear
axis, 0-0.3%); x = horizon T in steps; the dashed vertical line marks the
trained depth T=24, the star marks the validation-selected T*=16 (all
seeds); the point labels give exact recorded values.
**Key takeaway.** Longer thinking does not rescue Maze-hard: every seed
stays between 0.0% and 0.2% across T = 16-48 (only seed 1 leaves zero,
with 0.1% at T=32 and 0.2% at T=48, both metrics equal).
**Data source.** `data.csv`, block `tsweep` (`maze_hard_cf/results.json`).
**Caveats.** Recorded sweep values only; nothing between the swept horizons
is claimed. Points are single-seed full-test values - not aggregates, so no
error bars apply.

## maze_hard_examples.png - four example predictions

**Caption.** Four example predictions on tied test mazes: two CF-WallAware
(seed 0, T*=16) - the median-IoU maze (IoU 0.54) and the best-IoU maze
(IoU 0.95); two physics-arm exact solves (T=8) - the first maze the physics
read-out passes strict with a valid alternative route (maze 47: IoU 0.64,
strict pass, board-exact 0) and maze 0 (IoU 0.83, strict fail).
**How to read.** Dark green = predicted route cell that is also in the
reference route (hit); vermillion = predicted but not in the reference
(extra); blue = reference route cell missed; grey = free cell correctly
left unlit; black = wall; black boxes mark S and G.
**Key takeaway.** The reference route's cells are largely found, but the
predictions light extra cells (e.g. 100 extra on the median CF maze), and on
tied mazes the physics solver can land on a valid alternative route -
passing strict while necessarily failing board-exact. This panel is the
visual explanation of why exact < strict on tied mazes.
**Data source.** `example_grids.csv` (30x30 grids) plus per-panel stats in
`data.csv` (block `examples`, recomputed live from the CF seed-0 checkpoint
and the physics solver in live mode).
**Caveats.** Four hand-picked-by-rule instances; the whole-evaluation summary
is the coverage figure. CF panels show seed 0 only.

## maze_hard_coverage.png - per-instance IoU over ALL 1000 test mazes

**Caption.** Per-maze IoU with the reference route, sorted descending, for
CF-WallAware seed 0 at T*=16 (strict 0/1000), the physics exact solve at T=8
(strict 4/1000), and the WONN interim 52-epoch EMA prediction export
(its own budget, not the 150-epoch headline eval). This covers the full
evaluation set compactly - the galleries above show instances, this curve
shows every instance.
**How to read.** x = the 1000 test mazes sorted by per-maze IoU (highest on
the left); y = per-maze IoU in [0, 1] (1.0 = exact board match). Rings mark
the 4 mazes the physics arm passes with a valid alternative route, drawn at
each pass's true IoU position on the curve (maze 839: IoU 0.98; maze 47:
0.64; maze 785: 0.56; maze 958: 0.52) - three of the four sit mid-curve:
a strict pass can have a modest IoU, well below the highest-IoU mazes
(which are all strict failures).
**Key takeaway.** The reference route's cells are largely found (median IoU
0.73 physics / 0.54 CF), yet a single valid route almost never appears:
strict passes are physics 4/1000 and CF 0/1000. Finding the route is not
the bottleneck; committing to one clean route is.
**Data source.** `permaze_iou.csv` (one row per maze per arm; recomputed
live in live mode).
**Caveats.** IoU is computed with S and G counted as route cells. The WONN
curve is the labelled interim 52-epoch EMA export (path F1 0.48), which is
not the 150-epoch headline evaluation (path F1 84.0 EMA / 93.2 raw); the CF
curve shows seed 0 only. Nothing is aggregated, so no error bars apply.

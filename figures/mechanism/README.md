# Figures: mechanism (packet F3, F5)

Generated by `scripts/figures/mechanism.py` (CPU only). All numbers below come
from `data.csv` in this folder, which the script writes on every run. The two
baseline panels of F3 are extracted with the official model code from a
read-only baselines checkout whose location is passed via `--baselines-dir`
(or the `CF_BASELINES_DIR` environment variable); all paths below are
relative to that checkout or to this repository.

## f3_c1_embedding.png

Packet figure: F3

**Caption.** The per-cell input embedding of three models, each as channel
maps (first 8 channels) plus a 2-D PCA of the per-cell embedding vectors
coloured by cell type, one section per model, top to bottom: CF-Full c1(0)
(initial monomer concentration, 16 channels; hid 16, 160 epochs, trained at
fixed T=8, seed 0, one level-5 test maze, 11 x 11); AKOrN conditional input C
(the official code's nn.Embedding(10, 512) applied to the given digit, 512
channels; Sudoku, 100 epochs at T=16, single unseeded run: preliminary; one
test puzzle, 9 x 9); WONN natural frequency field omega (the per-token lookup
into MazeInputEmbedding.omega_template, 128 channels; maze-hard, 150 of 9000
epochs at T=24, seed 137 - reduced budget, not a reproduction - preliminary;
one maze-hard test maze, 30 x 30). Baseline panels come from the final EMA
checkpoints named in the run records.

**How to read.** Left: eight channel maps per section on one shared colour
scale per section, with that section's colour bar underneath. CF uses viridis
(dark = 0, bright = high concentration, 0 to 3.999); AKOrN and WONN use the
diverging RdBu_r scale, symmetric about white = 0 (+/-2.73 and +/-2.25 over
the shown channels). Right: each dot is one cell projected onto its first two
principal components (CF: PC 1 = 39.6%, PC 2 = 27.3%; AKOrN: 40.3%, 9.2%;
WONN: 99.5%, 0.4% of variance). Colours: grey = wall, sky blue = free
corridor, blue = path cell of the solution (CF only), orange = start, green =
goal; sudoku greys = blank cell, blues = given clue (counts in the legend).
Dots overlap exactly where cells hold the identical per-cell vector - that
overlap is real, not a rendering artefact.

**Key takeaway.** CF's c1(0) is spatially resolved (81 distinct per-cell
vectors among 121 cells; wall vs free centroids 1.88 pooled sd apart), and the
solution path is not yet marked (path vs free only 0.46 pooled sd). The
baseline per-cell input embeddings are per-token lookups: AKOrN's C takes only
10 distinct values among 81 cells (one per digit token present; all 43 blanks
share the digit-0 embedding; blank vs clue centroids 4.005 pooled sd apart),
and WONN's omega takes only 4 distinct values among 900 cells (one per input
token; wall vs free 18.09 PC units apart; every within-type spread is exactly
0). So for both baselines the input field cannot carry spatial structure
beyond the input token - any pathfinding must come from their dynamics.

**Data source.** CF: checkpoint `week2_results/followups/E1_CF-Full_seed0.pt`
(run record `week2_results/followups/results.json`); maze = index 0 of the
level-5 test split built by `scripts/run_week2.py load_data` (HF
`selimaktas/maze-curriculum-dataset`); c1(0) = `CFNet.initial_state` (softplus
of the encoder, c2(0) = 0). AKOrN: final EMA checkpoint
`akorn/runs/sudoku_akorn/ema_99.pth`, data `akorn/data/sudoku` (test split,
puzzle index 0), run record `akorn_tools/out/run_record.json`; extracted on
CPU with the official `SudokuAKOrN` (constructor flags match the run record's
official command), C computed as in the first lines of
`SudokuAKOrN.feature`. WONN: final EMA checkpoint
`WONN/runs/maze/wonn_reduced_L1T24_ch128_s137_bs32/ema_model.pth`, data
`wonn_tools/data/maze-30x30-hard-1k` (test split, maze index 0), run record
`wonn_tools/out/run_record.json`; extracted on CPU with the official
`MazeWinfreeNet` (ch=128, L=1, T=24, config from the run record); omega =
`f_init(inp)`, the `MazeWinfreeNet.feature` frequency field that with L=1
drives all T=24 steps.

**Caveats.** One instance per model (n = 121 / 81 / 900 cells): nothing is
aggregated, so there are no error bars or bands to clip. Single seeds: AKOrN
is one unseeded run (fewer than 3 seeds: preliminary), WONN is seed 137 only
(preliminary) and a reduced-budget run (150 of 9000 epochs, batch 32): not a
reproduction; CF is seed 0 of the 3-seed follow-up family. 8 channels shown per
model (of 16 / 512 / 128); the shared channel scales span only the shown
channels. PCA is computed per instance, so the components are
instance-specific. WONN's maze input has no path token: path cells of the
answer enter the input as free cells, so they can never be distinguished in
the omega field. AKOrN C and WONN omega are signed (embedding units; rad per
step).

## f5_invariants.png

Packet figure: F5

**Caption.** Guardrail invariants of the trained checkpoints at rollout length
T=64 over the first 64 mazes of the level-5 test split: maximum relative mass
drift max|M_t - M_0| / max(1, max M_0) per run (left, log scale) and minimum
monomer concentration min c1 over t = 0..64 per run (right), against the
pre-registered tolerances 1e-5 and -1e-7.

**How to read.** Each dot is one trained run (3 seeds per model; no
aggregation, so no error bars). Blue = CF-Full, green = CF-NoFrag. Left panel:
log-scale y axis; the dashed orange line is the mass tolerance 1e-5 - a dot
above it would fail. Right panel: symlog y axis (linear within +/-1e-7,
logarithmic beyond, because five runs report exactly 0, which a pure log axis
cannot show); the dashed orange line is the positivity tolerance -1e-7 - a dot
below it would fail.

**Key takeaway.** All 6 CF runs stay inside both tolerances: the worst mass
drift is 1.96e-6 (CF-Full seed 0), about 5x below the 1e-5 tolerance, and the
smallest min c1 is 0 (never negative; CF-Full seed 0 reaches 4.01e-15), far
above -1e-7. The JSON's overall verdict is 9/9 runs PASS (it also covers 3
RecurrentCNN runs, which have no concentrations and only check finite logits).

**Data source.** `week2_results/trained_invariants.json` (written by
`scripts/check_trained_invariants.py`; checkpoints `week2_results/CF-Full_seed<k>.pt`,
`week2_results/CF-NoFrag_seed<k>.pt`, tolerances and T=64 config recorded in
the same JSON).

**Caveats.** Per-run worst case over 64 mazes and 65 time points, not a mean;
dots are individual runs (n = 3 seeds per model, no sd shown because nothing is
aggregated). The min-concentration axis is symlog, not pure log, to
accommodate exact zeros; the linear zone +/-1e-7 is stated above. RecurrentCNN
runs appear only in the PASS count, not as dots, because they have no c1/mass.
No aggregated bands are drawn, so there is nothing to clip.

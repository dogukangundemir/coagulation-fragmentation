## Global decision rule (fixed in advance)

Every comparison below uses n = 3 seeds (0, 1, 2), paired by seed index because both arms are trained with the same seeds and the same data split. For a directional claim "A > B" computed from seed-level values a_0, a_1, a_2 and b_0, b_1, b_2:

- **SUPPORTED** only if mean(A) > mean(B), a_k > b_k for every seed k, and the mean paired difference mean(A) − mean(B) exceeds sd(d), where d_k = a_k − b_k are the per-seed paired differences and sd(d) is their sample standard deviation (n = 3, ddof = 1).
- **NOT SUPPORTED** if the opposite direction (B > A) meets the same three conditions.
- **INCONCLUSIVE** otherwise.

The variability threshold is the sd of the per-seed paired differences. This replaces an earlier draft of the rule that used the larger of the two arm standard deviations, sd(A) and sd(B); the paired threshold is the correct scale for this paired design because a seed that is hard for both arms (weak solver, unlucky split) inflates sd(A) and sd(B) together and would force INCONCLUSIVE even when all three paired differences d_k are positive and consistent — exactly the evidence the seed pairing was set up to use. The paired threshold remains deliberately conservative for n = 3. For within-model comparisons across T, the two "arms" are quantities from the same 3 checkpoints at the two T values, and d_k is the per-seed change between them.

Multiplicity: the rule yields seven directional comparisons in one family across the hypotheses above — H1, H2 primary, H2 secondary, H3, H4 — plus the two clauses of the supplementary settling hypothesis preserved in the appendix. No alpha correction is applied: this is a deterministic descriptive decision rule on summary statistics, fixed in advance, not an inferential test with controlled error rates. (When the original definitions were restored, the wall-aware H3 — absent from our earlier packet-derived numbering — joined the family; only this enumeration of ids was updated, the rule itself was not.)

Budget rule (fixed before verdicts): every arm of the Week-2 run is trained under one shared wall-clock budget (scripts/run_week2.py, --budget-minutes), and a run can be stopped early (epochs_done < planned, stopped_early). A directional verdict (SUPPORTED / NOT SUPPORTED) for any comparison below is computed only if every arm in that comparison finished its planned epochs (epochs_done == planned, not stopped_early); otherwise the comparison is INCONCLUSIVE, with epochs_done reported for each arm. An arm that merely received more training time than its opponent — or lost for lack of it — must not carry the verdict; early-stopped runs are reported descriptively only.

## H1 — CF-Full reaches the RecurrentCNN at T=8

**Original definition (notebook Section 0).** "CF-Full reaches the RecurrentCNN at T=8."

**Statement.** On the held-out level-5 test set (1,000 mazes), CF-Full (10,177 parameters) trained with the shared protocol reaches strict test accuracy at least as high as the parameter-matched RecurrentCNN at the training horizon T = 8. Directional claim for the decision rule: CF-Full > RecurrentCNN; parity within noise is INCONCLUSIVE under the rule. The wording "comparable at matched budget" is pre-registered as descriptive only, and permitted only inside an explicit equivalence band: |mean(CF-Full) − mean(RecurrentCNN)| < sd(d), the sample sd of the per-seed paired differences — the same noise scale the SUPPORTED threshold uses. Outside that band an INCONCLUSIVE verdict carries no equivalence reading; even inside it the wording is a descriptive summary, not an inferential equivalence test (no TOST, no error-rate claim).

**Packet citation.** Packet §0, p.1: "can a small looped network solve mazes ... by repeatedly merging and splitting internal 'particles'"; §2, p.4: does "coagulation-fragmentation [give] both high accuracy at small parameter budgets and better answers when the model is given more time to think"; §1.2, p.3, Week-2 deliverable: "Compare RCNN, CF-Full, CF-NoFrag"; §0 item 3, p.1: "a Stage-A CF network ... plus a parameter-matched RecurrentCNN baseline."

**Metric.** Strict test accuracy (headline metric of Packet §9.1, p.21-22: "the prediction must be exactly one legal, optimal S-to-G path"), mean over 3 seeds. IoU reported as a diagnostic only.

**Comparison and data needed.** CF-Full vs RecurrentCNN, both at T = 8 with the documented hyperparameters (Adam 1e-3, cosine decay, clip 1.0, batch 32, 40 epochs, BCEWithLogits with pos_weight). CF-Full is trained in the Week-2 run; the RecurrentCNN arm is likewise retrained in the Week-2 run under the shared protocol of scripts/run_week2.py, with the same seeds (0, 1, 2) as the CF arms — not the Week-1 checkpoints. (Packet §4.3, p.10 describes RecurrentCNN as one that "adds logits_at, loads Week-1 checkpoints", but the pipeline the Week-2 verdicts come from, scripts/run_week2.py, retrains every (model, seed) pair afresh, cf/train.py refuses any checkpoint whose run_id/fingerprint does not match, and no reuse_week1_rcnn path exists in the code; so the registered arm must match the pipeline.) Pre-committed: the H1 verdict is computed only from these retrained Week-2 RecurrentCNN numbers; the Week-1 per-seed numbers (Packet §5.1, p.12) are background at most and never feed H1, so the H1 pairing is within a single training run: CF-Full against RecurrentCNN, both trained afresh under the same protocol and the same seeds. Per-seed and mean strict accuracy on the bit-identical level-5 test split and the 1,000-maze unseen probes for levels 7 and 9; failure-type counts per maze.

**Decision rule.** As the global rule, arms = per-seed strict test accuracy of CF-Full and RecurrentCNN at T = 8.

**Known confounds.** (i) Ceiling: the supervisor judged the curriculum dataset too easy (Packet §6.1, p.13: "5x5 is too simple; do 30x30"), so a clean positive difference is hard here; the unseen-grid probes are the secondary diagnostic. (ii) Matched parameter count does not mean matched information flow: both models move information at most 2 cells per step (Packet §12.3, p.28), but their rate/readout structures differ. (iii) The comparison is CF's first run under this pipeline; disadvantages purely from implementation novelty are not separated from model quality.

## H2 — Fragmentation contributes: CF-Full vs CF-NoFrag

**Original definition (notebook Section 0).** "Fragmentation contributes (CF-Full > CF-NoFrag at T=8 and the gap widens for T > 8)."

**Statement.** CF-NoFrag (split flux forced to zero, otherwise identical layout) scores lower strict test accuracy than CF-Full at the training horizon T = 8, and the gap widens when the frozen models run past the training horizon (T > 8); the packet's own condition is Packet §7.5, p.17: "If fragmentation matters, CF-NoFrag should lose most when run past T_train." Primary directional claim for the decision rule: at T = 8, CF-Full > CF-NoFrag on strict test accuracy. Secondary claim under the same rule: the gap (CF-Full − CF-NoFrag) at T = 16 exceeds the gap at T = 8.

**Packet citation.** Packet §7.5, p.17: "Prediction for CF-NoFrag: c1 only decreases ... every merge is irreversible and for long T the state drifts towards 'all committed'. If fragmentation matters, CF-NoFrag should lose most when run past T_train. Caveat: its effective capacity is about 23% smaller"; §1.2, p.3, deliverable "No-fragmentation ablation"; §1.1, p.3, course checklist: "A CF version with and without fragmentation."

**Metric.** Strict test accuracy (§9.1), mean over 3 seeds, at T = 8 and at T = 16 (frozen weights); the invariant test that the split flux is exactly 0 and the split head receives exactly zero gradient is a precondition for the arm.

**Comparison and data needed.** CF-Full vs CF-NoFrag, both trained with the identical protocol and hyperparameters; per-seed strict accuracy on the level-5 test split at T = 8 and T = 16; the T-sweep curves for both; the observed c1/c2 trajectories (predicted drift towards "all committed").

**Decision rule.** Global rule; primary arms = per-seed strict accuracy at T = 8. The secondary claim is the same global rule applied to the per-seed gap differences: for each seed k, d_k = (CF-Full_k − CF-NoFrag_k)|_{T=16} − (CF-Full_k − CF-NoFrag_k)|_{T=8}. The secondary claim is SUPPORTED if all three d_k are positive, mean(d) > 0, and mean(d) > sd(d); NOT SUPPORTED if the opposite direction (all d_k negative, mean(d) < 0, |mean(d)| > sd(d)) meets the same three conditions; INCONCLUSIVE otherwise.

**Known confounds.** (i) Effective-parameter confound, fixed as a caveat in the packet: CF-NoFrag has 7,857 effective parameters vs CF-Full's 10,177 (Packet §12.3, p.28: "CF-NoFrag has fewer effective parameters (7,857 vs 10,177); mention it whenever CF-Full beats it"), so even the primary T = 8 advantage of CF-Full could be capacity and not dynamics; the T-dependence of the gap is the dynamics-specific signature, and a size-matched NoFrag variant is the clean follow-up. (ii) The two arms differ by construction in state evolution (irreversible merging), so the ablation removes a mechanism, not just a benefit: a bad score for CF-NoFrag past the horizon is consistent with both hypotheses honestly. (iii) CF-NoFrag is a strict subset of CF-Full's function class only at the dynamics level; the rate networks see different c2 fields during training, so the trained models are not clones at T = 8 either.

## H3 — Wall-aware helps: CF-WallAware vs CF-Full

**Original definition (notebook Section 0).** "Wall-aware helps (CF-WallAware > CF-Full)."

**Statement.** On the held-out level-5 test set at the training horizon T = 8, CF-WallAware — a CF-Full that builds the maze's wall geometry into its forward pass instead of learning it from data — reaches higher strict test accuracy than CF-Full when both arms are trained for the full 40 epochs under the identical protocol and the same seeds (0, 1, 2). Directional claim for the decision rule: CF-WallAware > CF-Full at T = 8 on strict test accuracy. The frozen-weights T-sweep and the unseen level-7 / 9 probes are diagnostics only.

**What the arms differ by** (cf/models/cf.py, MODEL_SPECS: "CF-WallAware" = CF-Full plus wall_aware=True; everything else — encoder, rate net, readout, reaction step, hyperparameters — is the CF-Full layout). Three changes, all driven by the free-cell channel of the input: (i) initial mass: the encoder output for the initial c1 field is multiplied by the free-cell mask, so no mass can start inside a wall; (ii) rate net: the hidden activations are gated by the free-cell mask, so reaction fluxes are only driven by free cells; (iii) readout: logits inside walls are masked to −20, so a wall cell can never be predicted as part of the path. The raw parameter count is identical to CF-Full (10,177, reported by both run books); the run bookkeeping counts 9,921 effective parameters for CF-WallAware (parameter entries that receive nonzero gradient, scripts/run_week2.py effective_n_params), against the packet's 10,177 raw and effective for CF-Full (Packet §12.3, p.28); both counts are reported wherever the comparison is reported.

**Metric.** Strict test accuracy on the level-5 test split at T = 8, mean over 3 seeds. Wall-hits per maze are reported as the diagnostic the arm is designed to eliminate (by construction the readout mask forces wall_hits = 0 for CF-WallAware; the count is descriptive, never a verdict input). IoU reported as a diagnostic only.

**Comparison and data needed.** CF-WallAware vs CF-Full, both arms trained by scripts/run_week2.py under the exact shared protocol: seeds 0, 1, 2; Adam 1e-3, cosine decay, clip 1.0, batch 32, 40 planned epochs, BCEWithLogits with the train's pos_weight; model selection on validation strict; the same --budget-minutes 45 flag. The CF-WallAware arm lives in week2_results/wallaware/ (week2_metrics.json there, produced via week2_results/wallaware/run_week2_wrapper.py, which calls run_week2.main() with --models CF-WallAware and the Week-2 protocol arguments, changing nothing else); the CF-Full arm is the main Week-2 run in week2_results/ (week2_metrics.json). Both arms ran on the same GPU (CUDA, NVIDIA GeForce RTX 3070 Ti) and finished all 40 planned epochs on all three seeds (epochs_done == planned, stopped_early == false) — the budget rule's precondition for a directional verdict is met by both arms. The two metrics files record different git commits (97f3f7a for the main run, 2fd7d5d for the wall-aware run); the diff between those commits touches only the cross_kernel plumbing, which is inactive in both arms (cross_kernel = False here), so the executed CF forward path is the same code. Per-seed and mean strict accuracy at T = 8 on the bit-identical level-5 test split; the frozen-weights sweeps over the same sweep_T grid and the unseen-grid probes as secondary evidence.

**Decision rule.** Global rule, arms = per-seed strict test accuracy of CF-WallAware and CF-Full at T = 8.

**Known confounds.** (i) The comparison changes inductive bias, not capacity: the wall constraint that CF-Full must learn from data (never predict a wall cell) is hard-coded in CF-WallAware, and the wall-hit failure channel is closed by construction (readout mask), so a strict-accuracy advantage may partly reflect a given constraint rather than a learned skill; CF-Full's wall-hits count measures how much of the gap that one channel can explain. (ii) Parameters are matched in raw count but not exactly in effective count (9,921 vs 10,177); both are reported with every verdict. (iii) The arms were trained in two invocations of the same runner (the wall-aware arm later, via the wrapper script, from a later commit of the same repository); the identical protocol, seeds, data splits, GPU and the budget rule's epochs check are the guard, but a training-environment difference beyond the recorded protocol cannot be fully excluded. (iv) As everywhere in this document, n = 3 seeds under the deliberately conservative paired rule: parity within the seed spread is INCONCLUSIVE, not evidence of no difference.

## H4 — Thinking longer: test-time T beyond the training horizon

**Original definition (notebook Section 0).** "Thinking longer (accuracy improves for T > T_train)."

**Statement.** For CF-Full with frozen weights, strict test accuracy at T = 16 (and 24, 32 as secondary points) exceeds strict test accuracy at the training horizon T_train = 8 on the level-5 test set; the direction is accuracy that rises when the model runs more iterations than it was trained with.

**Packet citation.** Packet §2.3, p.5, target "Thinking longer": "show that accuracy rises when the trained model runs more iterations than it was trained with"; §0 item 8, p.1, known weakness: "the model is trained only at T = 8 and accuracy drops for larger T (overthinking), despite perfect conservation"; §1.2, p.4, planned task: "Test T = 4, 8, 16 with frozen weights"; §4.3, p.10, notebook section 8: "frozen-weights T-sweep on grid 5 test and unseen grid 7 / 9".

**Metric.** Strict test accuracy at frozen weights via logits_at over sweep_T = [1, 2, 4, 8, 12, 16, 24, 32], mean over 3 seeds.

**Comparison and data needed.** CF-Full at T = 16 vs CF-Full at T = 8 (primary, within-model, paired by seed); the full sweep curve and the unseen-grid sweeps as secondary evidence; the same sweep for the RecurrentCNN as the planned contrast (its overthinking at T > T_train is the packet's stated weakness). Sweep JSON per model and seed.

**Decision rule.** Global rule applied to A = strict accuracy at T = 16, B = strict accuracy at T = 8, same 3 checkpoints per model.

**Known confounds.** (i) Nothing in training asks the dynamics to settle; the readout is only ever trained at step 8, so a collapse past the horizon would be a training-scheme artefact, not evidence against the mechanism. (ii) The 0.5 threshold on logits is held fixed across T although the logit scale can drift with steps. (iii) Information speed is 2 cells per step (Packet §12.3, p.28): on the unseen larger grids, larger T changes solvability mechanically, not only "quality of thinking", which is why the level-5 split is primary. (iv) Longer rollout accumulates float32 error; the mass-drift and positivity invariants must be re-checked at T = 64 before the sweep is trusted.

### H-A4 (old H4) — Settling: residual flux after the training horizon

**Statement.** For CF-Full, the residual flux Σ|m − s| / ΣM on test rollouts falls as the model runs past its training horizon (flux at step 16 lower than at step 8), i.e. the conserved dynamics approach the chemical equilibrium where ½ c1 σ(merge) = c2 σ(split); and in the same step range the RecurrentCNN's relative state change is larger at step 16 than at step 8 — that specific ordering is what the rule clause tests; a flat curve is INCONCLUSIVE, not evidence for the clause (the RecurrentCNN's state is not a conserved quantity). Primary clause for the decision rule: CF-Full residual flux at step 16 < CF-Full residual flux at step 8; contrast clause: RecurrentCNN relative state change at step 16 > at step 8.

**Packet citation.** Packet §7.2, p.15: "Equilibrium: a cell is at rest when ½ c1 σ(merge) = c2 σ(split). The residual flux Σ|m − s| / ΣM measures the distance from rest"; §4.3, p.10, notebook section 8: "settling curves (CF residual flux, RCNN relative state change)"; §10.3, p.25: "What conservation buys: stability at any T (contrast: the RecurrentCNN state is unbounded)"; §8 WP6, p.20, acceptance check: "settling curves fall after T_train" (the packet states this check for Maze-hard and the unseen larger curriculum mazes; H-A4 is evaluated on the level-5 test set — the deliberate scope reduction declared in the Scope line above).

**Metric.** CF-Full residual flux, recorded per step as Σ|g·m − g·s| / ΣM over the whole evaluation batch by logits_at(record=True) (g is the damping factor; on undamped runs g = 1 and this is exactly the packet's Σ|m − s| / ΣM), computed over the first 64 mazes of the level-5 test set at each step of a T = 32 rollout — exactly as cf/train.py settling_curve (default n = 64) is called by scripts/run_week2.py on data["test"]. Both settling quantities are computed on this same fixed 64-maze subset (not the full 1,000), so the within-model step-16-vs-step-8 comparisons below are on one fixed subset. RecurrentCNN relative state change, defined as the code computes it (cf/train.py, settling_curve; cf/models/rcnn.py): with h_0 = encoder(x) and the update h_t = h_{t−1} + cell([x, h_{t−1}]), the value at step t is ‖h_t − h_{t−1}‖₂ / ‖h_{t−1}‖₂, a per-step (not cumulative) quantity in which the full input-driven cell update counts; both norms are the global L2 norm over the whole evaluation batch tensor (one scalar per step, over all mazes, channels and cells together; the value is 0 if ‖h_{t−1}‖ = 0; list index t−1 holds step t). Both are settling-curve quantities, not accuracy.

**Comparison and data needed.** Per-seed (3 training seeds) mean residual flux at step 8 vs step 16 from one rollout of the frozen CF-Full checkpoints (logits_at already records the step states), and the matching per-seed relative state change for the RecurrentCNN; the whole settling curves for the figure.

**Decision rule.** Global rule applied clause-wise: (a) flux at t = 16 vs t = 8 for CF-Full; (b) state change at t = 16 vs t = 8 for RecurrentCNN. SUPPORTED only if the expected direction holds in both clauses under the rule; NOT SUPPORTED if the opposite of either clause meets the rule; otherwise INCONCLUSIVE.

**Known confounds.** (i) Low flux measures chemical rest, not answer quality: the state can settle onto a wrong, "all committed" configuration, so H-A4 is a mechanism claim and must be read jointly with the accuracy hypotheses — fragmentation (H2) and thinking longer (H4) above — never alone. (ii) The two settling quantities are different objects with different scales (a dimensionless normalized flux vs an unbounded state's relative change); only the within-model clause comparison is quantitative, never the cross-model magnitude. (iii) As with H4, training never asked for settling, so a flat or rising flux past the horizon is a live possibility and the verdict is expected to be negative-or-inconclusive without the later remedies planned in the packet (random T, damping, settling penalty). (iv) Flux is recorded on the same rollout as the accuracy sweep, so any bug in the step recording silently corrupts both thinking-longer (H4) and H-A4; the invariant re-checks at T = 64 are the guardrail.
